# 검증 기록

기반 작업의 검증 상태를 기록합니다. 정적 검사와 ZIP 확인, CLI 설치·목록 노출, 실제 Claude 답변과 외부 계정 확인을 구분합니다.

## 기반 검사

| 검사 | 상태 | 근거 |
| --- | --- | --- |
| npm 정적 검사 | 통과 | 플러그인 2개·스킬 5개·평가 사례 10개의 목록·문법·문서 연결 확인 |
| Claude 공식 형식 검사 | 통과 | Claude Code 2.1.318의 기본 프로필로 마켓플레이스와 플러그인 검사 |
| 기존 ZIP 내용·체크섬·재생성 | 통과 | 최초 업무 플러그인 ZIP 12개 항목의 바이트·CRC·SHA-256과 재생성 결과 확인. 다중 호스트 패키지는 변경 후 재검증 |
| 격리된 CLI 설치·목록 노출 | 통과 | 임시 CLAUDE_CONFIG_DIR에서 추가·설치·목록·details 명령 성공, 버전 0.1.0과 스킬 4개 확인 |
| GitHub Actions | 미실행 | 원격 저장소 게시 후 workflow 실행 |
| 외부 계정 웹·Cowork 설치 | 미확인 | 다른 회사 계정에서 원격 설치 필요 |
| 외부 계정 원격 업데이트 | 미확인 | 공개 버전 변경 후 반영 확인 필요 |

검사일은 2026년 11월 5일입니다. 제작 환경은 Node.js 22.20.0, Python 3.14.7, Claude Code 2.1.318입니다. 격리된 CLI 검증은 설정 폴더를 임시로 지정해 실행했으며 모델을 호출하지 않았습니다. 이 결과는 사용자 계정의 웹 설치나 실제 답변 품질 검증과 구분합니다.

기본 형식 검사는 통과했고 기존 JOINT 512×512 PNG 아이콘을 넣은 뒤 디렉터리용 아이콘 경고도 해소했습니다. 현재 배포 경로는 저장소 기반 마켓플레이스이며 공식 디렉터리 제출은 별도 단계입니다.

## 다중 호스트 테스트

테스트 대상은 `meeting-actions`의 `joint-meeting-actions`입니다. Claude Code 2.1.318, Codex CLI 0.166.0, Gemini CLI 0.67.0을 사용했습니다.

| 환경 | 설치·목록 | 실제 답변 |
| --- | --- | --- |
| Claude Code | 로컬 형식 검사 통과. 기존 업무 플러그인의 격리 설치는 통과 | 테스트 2건 모두 계정의 5시간 사용 한도로 실행 실패 |
| Codex CLI | 로컬 마켓플레이스 추가·설치·활성화 확인 | 정상 입력과 자료 부족 입력 2건 실행 완료 |
| Gemini CLI | 사용자 범위 설치와 `skills list` 노출 확인 | 미실행 |
| Claude 웹·Cowork | 미확인 | 미확인 |
| Codex 데스크톱 탐색 UI | 미확인 | 미확인 |

Codex 실행 기록에서 설치된 플러그인 캐시의 SKILL.md를 읽은 것을 확인했습니다. 정상 사례에서는 민지의 자료 전달 기한을 2026-11-09로 정리하고 가격 검토와 데모 제안을 구분했습니다. 자료 부족 사례에서는 담당자를 확인 필요로 남기고 회의 날짜가 없는 ‘다음 주’를 특정 날짜로 바꾸지 않았습니다. 가상 입력의 실제 출력은 [정상 사례](../evals/results/codex-actions-normal.md)와 [자료 부족 사례](../evals/results/codex-actions-incomplete.md)에 보관합니다.

Gemini의 작업 폴더 범위 설치도 성공했지만 해당 폴더가 신뢰되지 않아 목록에서는 제외됐습니다. 사용자 범위로 설치한 뒤 목록 노출을 확인했습니다. 실제 모델 실행에는 Gemini 인증과 사용 가능한 계정이 필요합니다.

공개 저장소, 원격 설치·업데이트와 전체 공개 검색 목록의 상태는 실제 게시 후 이 문서에 갱신합니다. Claude 포털은 현재 계정의 조직 게시 권한이 부족하고 OpenAI 포털은 게시자와 정책 정보가 미확정입니다. 자세한 항목은 [제출 준비](submission-preparation.md)를 참고해 주세요.

검사 스크립트에는 임시 사례 3개를 넣어 저장소 밖으로 향하는 플러그인 경로, 스킬 이름 불일치와 중복 YAML 키를 각각 거부하는지 확인했습니다. 이 임시 사례는 배포 파일에 포함하지 않습니다.

## 업무 품질 평가

아래 8개 사례의 입력과 기대 결과는 [cases.json](../evals/cases.json)에 있습니다. 각 사례를 Claude에서 실행한 뒤 사용 환경, 플러그인 버전, 실행일과 실제 출력을 근거로 상태를 갱신합니다.

| 사례 | 확인할 동작 | 상태 |
| --- | --- | --- |
| research-normal | 제공 자료의 범위와 접점 가설 구분 | 미실행 |
| research-incomplete | 동명 회사 식별에 필요한 질문 | 미실행 |
| meeting-normal | 30분 진행안과 미확인 질문 | 미실행 |
| meeting-incomplete | 미팅 목적 확인 | 미실행 |
| summary-normal | 데모 전달 합의와 검토 사항 구분 | 미실행 |
| summary-incomplete | 모호한 날짜와 미정 담당자 보존 | 미실행 |
| email-normal | 확인된 합의로 후속 메일 초안 작성 | 미실행 |
| email-incomplete | 수신자와 연락 목적 확인 | 미실행 |

설치와 스킬 목록 노출은 업무 품질 평가의 통과를 뜻하지 않습니다. 공개 안내에 지원 환경을 적을 때는 실제로 확인한 환경과 결과를 기준으로 합니다.
